# Phase 3：本地摄影语言方案

用户已明确授权继续 Phase 3。沿用现有十项参数与八项写入范围，不接入 AI，不分析照片，不增加 HSL、曲线、清晰度或去雾字段。

## 可行性与边界

明确的方向表达可以用本地词典映射为参数增量，但用户没有给出的幅度只能是项目默认建议，不能声称针对照片优化或保证视觉效果。因此输出规则名称、原句、幅度、解释与提示，先预览再应用。

首版包含曝光明暗、高光/阴影、对比度、白色/黑色、自然饱和度/饱和度及冷暖方向。标准幅度分别为曝光 0.20 EV、高光/阴影 20、其他滑块 10、色温 300 K；轻微为一半，明显为 1.5 倍。以上均是保守起点的产品约定，不是 Adobe 标准或图像分析结论。

“画面冷一点”可形成色温降低方案，但保留 Phase 2 白平衡写入阻断。“增加通透感”涉及尚不支持的清晰度/去雾，“肤色自然”“绿色不脏”涉及颜色或局部判断，“电影感”没有唯一参数含义，均明确拒绝，不部分执行。

## 结构与语义

- 独立 `semantics` 模块：版本化不可变词典、完整词组匹配、三档强度、来源与解释。
- 可混合 Phase 2 明确数字指令；用户的明确数字不随语义强度缩放。
- 逗号、分号或换行分隔；每句完整匹配，不做子串猜测。否定、未知表达与重复目标（包括相反方向）整批报错，不擅自抵消或覆盖。
- 抽出共用的操作预览层，仍基于同一个 XMP 快照完成范围检查、预览和保存；现有 Phase 2 命令行为不变。
- CLI `styles` 列出词典，`suggest` 只生成建议；`plan-style` 根据照片预览；`apply-style` 必须提供预览摘要，摘要绑定照片路径、XMP 原始字节、规则版本、匹配来源及结构化操作。旧预览或不同指令拒绝保存。纯 dry-run 不要求摘要。
- 摘要不替代文件并发检查、原字节备份或先关闭 ACR 的约定。缺失字段与越界继续报错，不补零、不截断。

## 验证顺序

1. 词典与解析：默认幅度、强度、明确数字、否定与冲突、无文件副作用。
2. 方案预览与应用：非零基线、白平衡阻断、摘要绑定、外部修改、批量原子写入和非目标元数据保留。
3. CLI 与 Phase 1/2 全量回归；源码包、wheel 和独立安装检查。
4. 对独立命名的真实副本只执行已支持参数；文件验证与新增 ACR 人工验收分别记录。
5. 独立分支、草稿 PR、文档与进度保存。额度 <=20% 时停止新增开发并保存；完成本阶段也不自动进入 Phase 4。
