# Phase 4：AI 辅助参数方案

用户已授权继续下一阶段。模型只产生建议，本地程序决定是否满足既有显影参数和文件保护规则。

## 首版范围与流程

1. 读取当前 XMP，构造仅含已记录参数、缺失字段、处理版本和白平衡的模型上下文。不传文件路径、完整 XMP、RAW 或无关元数据。
2. 从本机 JSON 配置读取服务商、模型名、环境变量名、超时与输出上限。密钥不存入配置或结果，不自动选择付费模型；真实调用须有有效配置。
3. `ai-plan` 显式请求一次建议。默认只发送文字与参数；只有同时给出 JPEG/PNG 预览路径和 `--send-preview` 才准备和发送图片。不自动导出或上传用户照片。
4. 图片仅用于建议参考：限制源大小与像素数，按方向缩小并重新编码 JPEG，剥离 EXIF/其他元数据；建议由用户提供当前照片的 sRGB 预览，程序无法证明图片与 NEF 对应。
5. AI 输出只允许 JSON 对象，字段为 adjustments、explanation、warnings。每项只能给既有参数名和最终绝对数值；重复、未知、非数字、非有限、超范围、过度精度、空方案均拒绝。模型不能提供命令、文件路径或待执行代码。
6. 根据请求前的 XMP 快照验证返回结果；等待模型期间 XMP 变更时停止。缺失字段不补零，白平衡保持整批阻断。
7. 保存独立 `.lumina-plan.json` 方案，拒绝覆盖已有文件。摘要绑定输入请求、模型来源、预览图摘要、目标照片、XMP 原字节及完整建议。保存后的方案可离线 `ai-show` 重新核对当前前后值。
8. `ai-apply` 仅使用已保存方案，必须提供已核对的方案摘要；不再次调用模型。校验源 XMP 未变，再沿用原字节备份、临时校验与安全替换。

## 接口与故障规则

首版准备 OpenAI Responses 与 DeepSeek Chat Completions 适配；模型名由用户配置，其他服务商按相同建议协议扩展，不冒充已在线验证。

OpenAI 使用结构化输出和 `store=false`。DeepSeek 使用 JSON 输出模式并给出结构示例。服务商的格式承诺不替代本地检查。首版 DeepSeek 仅启用文字通路，不推断所选模型支持图片。

网络超时、认证失败、限流、重定向、超大响应、拒绝、截断与格式错误均停止，不自动重试以免重复计费，不把服务端错误正文、请求或密钥打印到终端。不在执行应用时自动联网。

方案摘要用于检查内容是否与审核时一致，不是对恶意本地修改的数字签名。用户明确执行应用命令才进行写入。所有真实方案、配置和图片留在 `.local/` 或其他被忽略位置。

## 验证

先用人工 JSON、假客户端和模拟 HTTP 响应覆盖正常、拒绝、截断、参数越界、过期方案、错误脱敏及上传边界；测试不调用付费服务。再验证打包和既有全部回归。服务商真实 API 与真实图片上传需使用用户提供的配置并单独记录；不能用模拟结果代替在线验收。

依据：[OpenAI 结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs)、[图像输入](https://developers.openai.com/api/docs/guides/images-vision)、[DeepSeek JSON 模式](https://api-docs.deepseek.com/guides/json_mode/)、[Pillow 图像方向处理](https://pillow.readthedocs.io/en/stable/reference/ImageOps.html)。查阅于 2026-09-30。
