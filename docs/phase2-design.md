# Phase 2：明确参数指令与安全应用

2026-09-30 用户授权继续开发。本阶段把明确文字参数转换为结构化操作，不实现“电影感、通透、冷一点”等 Phase 3 摄影语义，不调用 AI 或外部 API。

## 语义约定

原规范的 `曝光+0.3，高光降低40，阴影提高30` 表达带方向的调整。仅输出数字无法区分“增加”与“设为”，因此每项操作同时记录 `parameter`、`operation`（`set` 或 `adjust`）和 `value`。

| 指令 | 操作 | 结果（原曝光 0.25 时） |
|---|---|---|
| 曝光+0.3 / 曝光增加0.3 | adjust +0.3 | 0.55 |
| 曝光降低0.3 | adjust -0.3 | -0.05 |
| 曝光设为+0.3 / Exposure=0.3 | set 0.3 | 0.30 |
| 曝光 0.3 | 拒绝：未说明赋值或增减 | 不修改 |

支持十个既有参数的中文名与英文字段名、全角数字/符号、逗号/分号/换行分隔，曝光可带 EV，色温可带 K。参数名与操作动词来自明确白名单；整条输入必须完整解析。重复参数、方向冲突、未知条目、非有限数字和无效单位均报错，不部分执行，也不猜测遗漏的数值。

## 分层

1. `parser`：不访问文件，把文字转为不可变操作列表。
2. `adjustments`：基于同一份 XMP 快照计算 before/after、范围和精度检查、可应用状态。
3. `xmp.writer`：接受显式最终值，同一批更新只有一次备份与一次替换；保留 Phase 1 的原件检查和往返校验。
4. CLI：`parse` 只解析；`plan` 读取但不写文件；`apply` 显式保存，支持 `--dry-run`。保留原 `read` / `set-exposure` 用法。

## 范围与保存规则

- 十项参数均可解析和预览。写入仅开放 Exposure、Contrast、Highlights、Shadows、Whites、Blacks、Vibrance、Saturation 八项，目标字段必须已存在。
- Temperature/Tint 的预览不是已验证的白平衡方案。涉及这些参数时整批应用拒绝，说明白平衡模式尚未支持；不静默忽略或只应用剩余条目。
- 基础数值检查：曝光 [-5,5] EV、最多两位有效小数；其余可写参数为 [-100,100] 整数。色温预览 [2000,50000] K、色调预览 [-150,150] 整数。
- 相对调整需要 XMP 中已记录的当前值；当前值缺失时不补零。既有字段或版本不合法时拒绝保存。
- plan 输出源 XMP SHA-256；apply 可以携带预览得到的摘要，防止在预览后文件改变的情况下应用旧方案。应用内部的相对计算与写入共用一次快照，避免再次读取后误套增量。
- 拒绝整批中的任何非法值；不截断到范围边界，不静默舍入。相对操作再次执行会再次调整，明确提醒用户；绝对赋值的重复执行保持幂等。
- 先完整验证，再一次性修改内存文档、备份和替换。纯预览和无变化计划均不写文件。
- 保持现有 ProcessVersion 15.4 范围。新八项参数的文件级测试与 ACR 实机结果分开记录，不把 Phase 1 曝光实测泛化到全部参数。
- 当前照片主体及其祖先不接受 XML Base，避免空 `rdf:about` 实际解析为其他文件；`rdf:about` 与 `rdf:ID`/`rdf:nodeID` 并存时拒绝。嵌套非目标元数据仍保留。依据：[W3C RDF/XML 主体标识与基准 URI](https://www.w3.org/TR/rdf-syntax-grammar/#section-Syntax-ID-xml-base)。
- 数值计算使用自身精度环境，不修改宿主 Decimal 上下文，也不因宿主舍入设置改变结果。

## 实现与验收顺序

1. 完成解析器，用原规范例句、正反向数值、全角输入、边界和无效语句验证。
2. 完成预览计划，用非零基线检查赋值与增量差异、缺失与越界处理、白平衡应用阻断。
3. 扩展 XMP 的批量最终值保存，保留已有曝光接口；检查一次备份、失败无部分写入、非目标内容不变及并发变化拒绝。
4. 接入 CLI，验证 UTF-8 JSON、退出码、标准错误分离与完整命令流程。
5. 用独立命名的真实副本做文件级验证，原片与原 sidecar 不写入；新参数的 ACR 界面验收需要另行记录。
6. 更新说明、变更记录和交接状态，保存独立分支与草稿 PR。每个里程碑检查账户 5 小时剩余额度，触及 <=20% 时停止新增工作并收尾。
